## 00:00–00:30 ｜封面（P1）

大家好，我们是「代码仓鼠」。

先记住一句话：**你写代码，它吃饭。**

它不是工具，是一只住在你 GitHub 仓库里的电子宠物。输入用户名，3 秒领养；你提交，它吃饭；你摆烂，它会饿、会 emo，14 天它会离家出走。

今天不讲架构，先给大家看一只饿了七天的仓鼠。

## 00:30–01:10 ｜共鸣（P2）

每个开发者的备忘录里，都躺着几个「有空就做」的点子。

不是做不了，是「正经项目」永远排在前面。于是 commit 一拖再拖，代码里的刺没人看第二眼，写代码变成流水线。我们想让这件事重新有一点温度——所以，把仓库拟人化成一只仓鼠。

## 01:10–02:00 ｜机制（P3）

玩法很简单：输入 GitHub 用户名，只读公开仓库。

我们读三样东西：提交频率、commit message、最近一次 diff。它们会变成四个状态：体重、心情、饥饿、亲密度。

一次 commit 等于一颗瓜子；7 天不写它 emo；14 天它离家出走；投喂一颗瓜子，它可能会回来。

## 02:00–02:40 ｜产品演示（P4）

产品打开就能玩。左边是领养入口，下面是它的窝、贡献图、状态条。

门槛故意降到零：不用登录、不用授权。现场可以把用户名给我，30 秒后你就能看到一只属于你的仓鼠，以及它的第一句吐槽。

右上角「Kiro Hook 已连接」——保存代码就能投喂。

## 02:40–03:20 ｜高光（P5）

它还有一个很好玩的腮帮子：读取最近一次 diff，给三条轻量提示。

不是正式 code review，也不说教，用仓鼠的语气吐槽你。比如 JSON.parse 没包 try/catch，它会说「崩了一下牙」。

它还会生成一张 4:5 的体检报告，保存、发群、发朋友圈都行。

## 03:20–04:20 ｜Kiro 深度（P6）

重点是：整个东西是 Kiro 做的。

Quick Spec 把一句话拆成需求、设计、任务；并行 tasks 同时跑前端、后端和测试；三个 Crew 子 Agent 负责仓鼠人格、commit 考古和界面。

最关键的一步是 Agent Hook：在 Kiro 里保存代码，Hook 自动跑测试，并 curl 一下 `/feed`，仓鼠当场吃瓜子。

**Kiro Hook 不只是开发工具，它成了产品的消化系统。**

多模型方面，Claude 写人格，DeepSeek 审代码，Auto 负责调度。

## 04:20–04:50 ｜为什么会被传播（P7）

为什么它会被转发？

第一，名字就是梗，仓库的仓、仓鼠的鼠，30 秒讲得清。
第二，每个人玩的是自己的仓库，看到的是自己的摆烂和卷。
第三，体检报告天生适合晒。

它没什么用，但它具备传播的所有要素。

## 04:50–05:00 ｜收尾（P8）

最后一句话：**它没什么用，但你会因为它，想多写一行好代码。**

这就是「无用之用」。谢谢大家，欢迎现场领养，也欢迎问我 Kiro 到底怎么用。

## Q&A 预备（8 题）

**1. 这不就是 GitHub 贡献图吗？**
贡献图是数据可视化；我们是有情绪、会饿、会离家出走、会藏 bug 的活物，而且 Kiro Hook 是它的运行机制。

**2. 有什么用？**
「无用之用」——它让你愿意写代码，还顺手做了轻量 review。评审标准也是这么写的：不关心立刻改变世界，只关心点子够不够鬼。

**3. AI 在哪里？**
Kiro 是开发 Agent；产品里的人格文案、轻量审查、界面由 Kiro / Crew 产出并沉淀成引擎；运行时也不依赖外部 API，断网可演。

**4. 离开 Kiro 能做吗？**
做不了这个闭环：Spec 驱动 + 并行 tasks + Agent Hook 是 Kiro 原生的开发方式，Hook 直接就是产品的消化系统。

**5. 数据隐私怎么办？**
只读公开仓库，不登录、不写数据库、不在前端存密钥；现场可以让评委自己输用户名。

**6. 为什么不做成 App？**
150 分钟里，网页是最快能让评委玩上的形态；而且分享卡天生适合社交传播。

**7. 现场能复现吗？**
能。组件库 + Spec + 提示词都在工程包里，150 分钟按波次组装；演示档案兜底。

**8. 你们最想让评委记住什么？**
一句话：**你写代码，它吃饭。** 一个动作：**保存代码，仓鼠进食。**
