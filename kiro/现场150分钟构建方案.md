# 现场 150 分钟构建方案 · 代码仓鼠

> 适用：Kiro 鬼点子计划 · 线下赛（长沙 / QCon 上海现场）。
> 原则：**组件复用、主体现场造**。规则原文：「不得使用赛前已完成的项目主体（自有代码组件复用不限）」。
> 因此本工程包里的 `app/` 是**组件库 + 参考实现**，不是直接交上去的成品。现场用 Kiro 按 Spec 重新生成页面主体与交互，保留 Spec / tasks / Hook 执行记录。

---

## 0. 合规红线（务必看）

- 允许：复用自己写过的 SVG 组件、设计 token、状态公式、文案库、Canvas 渲染函数、本地服务脚本。
- 不允许：把 `app/` 整个项目拷进去当「现场成果」；不允许使用赛前完成的页面主体与交互。
- 做法：现场在 Kiro 里新建 `repo-hamster` Spec，按 `kiro/specs/repo-hamster/tasks.md` 的波次实现；组件从本工程包复制，页面结构与交互现场写。
- 留下过程证据：Spec 三件套、tasks 勾选记录、Hook 执行记录、Git 提交时间线。

## 1. 现场分工（3 人最佳；1 人也能做）

| 角色 | 负责 |
|---|---|
| 主讲 / 产品 | 定范围、写文案、控制演示节奏、最后路演 |
| 前端 | 页面结构、状态条、投喂动画、分享卡 |
| 数据 / 引擎 | GitHub 接入、状态公式、bug 启发式、兜底档案 |

一个人：按「数据层 → 状态 → 页面 → Hook → 投喂」顺序做，砍掉 bug 清单与分享卡。

## 3. 演示动线（评委走到工位时，90 秒版）

1. **10 秒**：递上一句「你写代码，它吃饭。」屏幕上仓鼠在呼吸。
2. **20 秒**：请评委报自己的 GitHub 用户名 → 输入 → 3 秒出结果：它的体重、心情、饥饿、亲密度和一句吐槽。
3. **20 秒**：点「投喂」→ 瓜子落下、仓鼠咀嚼、状态条变化。
4. **20 秒**：在 Kiro 里改一行代码保存 → Hook 触发 → 页面仓鼠当场吃东西（最高光）。若 Hook 不稳，切回按钮投喂。
5. **10 秒**：打开「腮帮子里的 bug」→ 三条轻量提示。
6. **10 秒**：生成体检报告 → 一张可保存的卡片。
7. **收尾**：「没什么用，但你会因为它想多写一行好代码。」

## 5. 兜底预案

| 情况 | 处理 |
|---|---|
| GitHub 打不开 | 用演示档案；解释「真实数据接口在，现场网络不稳，切演示快照」 |
| Kiro Hook 不触发 | 先点按钮投喂，再说「Hook 配置在这里，我可以放录屏」 |
| 投影分辨率低 | 用 1440 宽度布局；浏览器放大 110%；只演示首屏 |
| 时间不够 | 砍 bug 清单和分享卡，保领养 + 状态 + 投喂 + Hook |
| 评委问「这算不算 AI」 | 讲 Kiro 的 Spec 并行 + Hook 闭环，别争「产品里有没有大模型」 |

## 6. 30 秒电梯稿

> 这是代码仓鼠。输入你的 GitHub 用户名，3 秒领养一只住在仓库里的仓鼠：你写代码它吃饭，你摆烂它 emo，14 天它会离家出走。它还会把 diff 里漏掉的 bug 藏进腮帮子，生成一张可以晒的体检报告。全程用 Kiro 做，Kiro Hook 保存代码就会投喂它——Kiro Hook 就是它的消化系统。没什么用，但你会想多写一行好代码。
