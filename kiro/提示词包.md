# 提示词包 · 现场用 Kiro 在 150 分钟内造出「代码仓鼠」

> 把下面的提示词按顺序粘进 Kiro 即可。工程包里的 `app/` 只作为**可复用组件**（SVG 仓鼠、设计系统、分享卡渲染、状态公式），页面主体与交互请现场用 Kiro 重新生成，保留 Spec / tasks / Hook 执行记录作为过程证据。

---

## 1. 起 Spec（Quick Spec）

> 用 Kiro 新建 Feature Spec，名称 `repo-hamster`，类型 Feature，一句话需求：
>
> 输入一个 GitHub 用户名，生成一只住在该用户仓库里的仓鼠：根据最近 commit 的频率、时间和 commit message 质量计算体重、心情、饥饿、亲密度，并说一句吐槽；读取最近一次 commit 的 diff，给出 3 条「仓鼠藏起来的 bug」；生成一张可下载的 1080×1350「仓鼠体检报告」分享卡；支持 Kiro Agent Hook 保存代码时投喂。
>
> 技术约束：Next.js 15 App Router 或纯 HTML/CSS/JS 均可，单页面，无数据库，部署 Vercel；GitHub REST API，无 token 时用缓存与演示快照兜底；文案引擎内置，不依赖外部模型 API；仓鼠用内联 SVG，不引入 3D；所有素材本地化，不依赖 CDN。
>
> 验收：任意公开 GitHub 用户名 3 秒内出结果；7 天无提交显示 emo，14 天显示离家出走；diff 审查输出 ≤3 条；分享卡可下载 PNG；断网时可切演示档案。

生成后检查三件套：`requirements.md`、`design.md`、`tasks.md`，并让 Kiro 按 tasks 依赖图并行执行。

## 2. 分波实现提示词

**Wave 1（并行）**
> 实现 tasks 里 Wave 1 的 T1–T3：项目骨架与设计 token、GitHub 数据层（10 秒超时 + 错误兜底）、仓鼠 SVG 四状态组件。三个任务相互独立，并行执行；完成后跑一遍本地预览确认无控制台报错。

**Wave 2**
> 实现 T4–T7：状态引擎与文案、主界面与四状态条、投喂闭环、演示档案兜底。状态公式按 design.md；投喂后 2.6 秒恢复；连续点击不崩；输入框为空时抖动提示。

**Wave 3**
> 实现 T8–T10：腮帮子 bug 清单（diff 启发式 + 严重度排序 + 空结果兜底）、Canvas 体检报告（1080×1350）、Kiro Hook 投喂（本地 `/feed` + SSE）。先做 T8，再做 T9 与 T10，后两者可并行。

**Wave 4**
> 做 T11–T13：统一文案与视觉、跑完整演示流程、准备 30 秒与 5 分钟两版路演。检查 390px / 1440px / 1920px 三个宽度无横向滚动。

## 3. Crew 子 Agent 提示词

**仓鼠人格设计师**
> 你是一只住在 GitHub 仓库里的仓鼠，名字由用户名生成。请为一组数据（提交频率、最近提交时间、commit message 质量、仓库语言）生成：1 句见面语、3 句日常吐槽、投喂反馈、emo 台词、离家出走留言。语气可爱、嘴硬心软、不低俗，每句不超过 40 字，中文。

**commit 考古学家**
> 读取最新一次 commit 的 diff，找出最多 3 个「值得提醒但不必上纲上线」的点（如 console.log、空 catch、any、硬编码密钥、大改动无测试、TODO）。每条给出：严重度（hot/medium/mild）、文件:行、一句人话标题、一句仓鼠语气的解释。不要输出正式 code review 的套话。

**界面画师**
> 用内联 SVG + CSS 画一只奶油金色的仓鼠：圆脸、大腮帮子、粉色腮红、门牙、小爪子。需要 happy / hungry / emo / eating 四种状态，以及呼吸、眨眼、耳朵、爪子、咀嚼、眼泪、乌云动画。风格：贴纸感、可爱、干净。

## 4. Hook 提示词

> 在 Kiro 的 Agent Hooks 面板新建一个 Hook：名称「投喂仓鼠」，事件 `fileEdit`，监听 `app/**/*.js`；动作是让 Agent 先运行 `npm test`，通过后执行 `curl -X POST http://localhost:5173/feed`。把生成的 `.kiro/hooks/feed-hamster.kiro.hook` 留在仓库里，现场演示保存代码 → 仓鼠进食。

## 5. 提交用 200 字说明（定稿，198 字）

> 代码仓鼠：在你的 GitHub 仓库养一只仓鼠。输入用户名领养，它按最近提交决定胖瘦与心情——写代码它吃饭，连续摆烂会 emo 出走；还会把最近 diff 里漏掉的 bug 藏进腮帮子，生成可分享的「仓鼠体检报告」。全程用 Kiro：Quick Spec 拆需求、任务并行执行；Crew 三个子 Agent 管仓鼠人格、commit 考古和界面；Agent Hook 在保存代码时跑测试并投喂——Kiro Hook 就是它的消化系统。

## 7. 评审 Q&A 预备

- **AI 在哪？** Kiro 是开发 Agent；产品内的人格文案、轻量审查、界面都由 Kiro/Crew 产出并沉淀为引擎。
- **和 GitHub 贡献图有什么区别？** 贡献图是可视化；这是有情绪、会饿、会离家出走、会藏 bug 的活物，而且 Hook 是它的运行机制。
- **有什么用？** 这是「无用之用」；它让你愿意写代码，还顺手做了轻量 review。
- **离开 Kiro 能做吗？** 做不了这个闭环：Spec 并行任务 + Agent Hook 是 Kiro 原生的开发方式。
