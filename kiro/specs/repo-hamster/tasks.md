# tasks.md · 代码仓鼠（repo-hamster）

> Kiro Feature Spec 的「任务」产物。按依赖关系分波，独立任务可并行；括号内为现场预估。

## Wave 1 · 地基（可并行，约 25 min）

- [ ] **T1 工程骨架**（10 min）
  - `app/index.html` + `css/style.css` 设计 token、顶栏、舞台、面板骨架
  - 验收：本地打开有完整布局，无控制台报错
- [ ] **T2 GitHub 数据层**（15 min）
  - `fetchUser / fetchRepo / fetchCommits / fetchCommitDetail`
  - 10s 超时、错误捕获、返回统一数据形状
  - 验收：输入 `torvalds` 能拿到仓库与最近 30 条提交
- [ ] **T3 仓鼠 SVG 组件**（15 min）
  - `Hamster.svg(state)`：happy / hungry / emo / eating 四状态
  - 呼吸、眨眼、耳朵、爪子动画
  - 验收：四状态切换正常，240–640px 下都可爱

## Wave 2 · 核心体验（依赖 Wave 1，约 45 min）

- [ ] **T4 状态引擎 + 文案**（15 min，依赖 T2）
  - 四个状态公式、状态机（happy/hungry/emo/runaway）
  - 每状态 ≥ 3 条吐槽文案；投喂/emo/离家出走文案
  - 验收：7 天 / 14 天阈值正确；投喂数值变化正确
- [ ] **T5 主界面与状态条**（15 min，依赖 T1/T3/T4）
  - 领养表单、报告面板、四个状态条、气泡、周历
  - 验收：输入用户名 3 秒内出首屏；移动端无横向滚动
- [ ] **T6 投喂闭环**（10 min，依赖 T5）
  - 进食动画、瓜子粒子、Toast、状态更新
  - 验收：连点不崩；离家出走被投喂 → 回到 emo
- [ ] **T7 演示档案兜底**（5 min，依赖 T4）
  - 3 只演示仓鼠（卷王/摆烂/普通）+ 失败自动回退
  - 验收：断网时仍可完整演示

## Wave 3 · 加分项（依赖 Wave 2，可并行，约 45 min）

- [ ] **T8 腮帮子 bug 清单**（15 min，依赖 T2）
  - diff 启发式、严重度排序、空结果兜底
  - 验收：最新提交产出 ≤3 条，含文件位置与人话解释
- [ ] **T9 体检报告分享卡**（20 min，依赖 T5）
  - Canvas 1080×1350：仓鼠、名字、四状态、瓜子/bug、quote、署名
  - 验收：PNG 可下载，缩略图在页面中不糊
- [ ] **T10 Kiro Hook 投喂**（10 min，依赖 T6）
  - `server.mjs` 的 `/feed` + `/events`；`.kiro/hooks/feed-hamster.kiro.hook`
  - 验收：Hook 触发后 500ms 内页面进食并提示来源

## Wave 4 · 收尾（约 20 min）

- [ ] **T11 文案与视觉打磨**（10 min）
  - 错别字、emoji、状态文案、阴影/圆角统一
- [ ] **T12 部署与录屏**（10 min）
  - Vercel 部署或本地录屏 3–5 分钟；200 字说明
- [ ] **T13 演示彩排**（5 min）
  - 30 秒开场 + 90 秒主流程 + 30 秒 Kiro 证据链 + 收尾

## 并行波次示意

```
Wave 1:  T1 ─┬─ T2 ─┬─ (T4/T5/T8 依赖)
             └─ T3 ─┘
Wave 2:  T4 → T5 → T6 → T7
Wave 3:  T8 ∥ T9 ∥ T10
Wave 4:  T11 → T12 → T13
```

| 16:05–16:10 | 检查网络/投屏/本地服务，准备评审预审 | 全员 |

## Definition of Done

- [ ] 输入任意公开 GitHub 用户名 → 3 秒内出仓鼠
- [ ] 7 天 / 14 天状态切换肉眼可见
- [ ] 投喂有动画、有反馈、数值变化正确
- [ ] Kiro Hook 保存代码 → 仓鼠进食（或录屏兜底）
- [ ] 断网时演示档案可完整跑通
- [ ] 现场 5 分钟能讲完：痛点 → 产品 → 魔法 → Kiro 深度 → 收尾
